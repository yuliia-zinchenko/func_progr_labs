# Лабораторна робота №1, варіант 2

**Інформаційна система «Розклад роботи дисплейних класів факультету»**

Програма на Haskell з базою даних MySQL. Має два інтерфейси: консольне меню і веб-сторінку.
Обидва працюють через ті самі власні класи типів (`class`) та їх екземпляри (`instance`) для кожної таблиці.

## Налаштування бази даних

```bash
brew services start mysql

# користувач, під яким працює програма
mysql -u root -e "CREATE USER 'lab_user'@'localhost' IDENTIFIED BY 'lab_pass';
                  CREATE USER 'lab_user'@'127.0.0.1' IDENTIFIED BY 'lab_pass';
                  GRANT ALL ON display_classes.* TO 'lab_user'@'localhost';
                  GRANT ALL ON display_classes.* TO 'lab_user'@'127.0.0.1';"

# структура БД і тестові дані
mysql -u root < sql/schema.sql
mysql -u root display_classes < sql/seed.sql
```

`schema.sql` видаляє і створює БД наново, тому його повторний запуск повертає базу до початкового стану.

## Запуск

```bash
cabal update
cabal run display-classes
```

Веб-інтерфейс (запускати з папки проєкту, бо сторінка читається з `web/`):

```bash
cabal run display-classes -- --web
```

Потім відкрити в браузері <http://localhost:8080>. Інший порт: `cabal run display-classes -- --web 3000`.
Зупинити сервер: `Ctrl+C`.

Параметри підключення за замовчуванням: `127.0.0.1:3306`, користувач `lab_user`, пароль `lab_pass`,
БД `display_classes`. Їх можна змінити змінними середовища `DB_HOST`, `DB_PORT`, `DB_USER`,
`DB_PASSWORD`, `DB_NAME`, наприклад:

```bash
DB_USER=root DB_PASSWORD= cabal run display-classes
```

## База даних (9 таблиць)

| Таблиця | Зміст |
|---|---|
| `classrooms` | дисплейні класи: номер, корпус, поверх, кількість місць, години роботи |
| `workstations` | робочі місця: клас, номер місця, інвентарний номер, CPU, RAM, ОС, стан |
| `users` | користувачі: ПІБ, роль (студент/викладач/адміністратор), група, контакти |
| `teachers` | викладачі: кафедра, посада (посилання на `users`) |
| `disciplines` | дисципліни та кількість годин |
| `schedule` | розклад планових занять: клас, викладач, дисципліна, група, день, час, тип, період дії |
| `free_access` | час вільного доступу до класів, черговий |
| `workstation_sessions` | фактичне використання робочих місць (для обліку завантаженості) |
| `maintenance_log` | журнал обслуговування робочих місць |

Представлення `v_classroom_load` і `v_workstation_load` рахують завантаженість класів і робочих місць.
Цілісність даних забезпечують зовнішні ключі, `UNIQUE`, `CHECK` та `ENUM`.

## Функціонал

**Керування даними.** Для кожної з 9 таблиць: перегляд усіх записів, пошук, додавання,
редагування і видалення з підтвердженням.

- У консолі пошук іде за ID, а при редагуванні порожнє введення залишає старе значення.
- У веб-інтерфейсі є пошук по всіх полях. Редагування відкривається кліком по рядку.
  Зовнішні ключі вибираються зі списку за назвою (клас, викладач, користувач).

Перед збереженням програма перевіряє (однаково для консолі і вебу):
- формат і обовʼязковість полів (час `HH:MM`, дата `YYYY-MM-DD`, значення зі списку);
- прості правила: час початку раніше за кінець, кількість місць > 0, студент має групу тощо;
- правила, для яких потрібна БД:
  - заняття не накладаються за класом, викладачем чи групою;
  - заняття і вільний доступ не виходять за години роботи класу і не перетинаються;
  - сеанс можливий лише на справному місці і лише один одночасно;
  - номер місця не більший за місткість класу;
- обмеження БД; помилки показуються зрозумілим повідомленням, наприклад, що запис використовується в іншій таблиці.

**Звіти та запити:**
1. Тижневий розклад класу (заняття та вільний доступ)
2. Розклад викладача
3. Розклад навчальної групи
4. Час вільного доступу всіх класів
5. Вільні робочі місця на задану дату й час
6. Завантаженість класів за тиждень (години, %, діаграма)
7. Завантаженість робочих місць за весь час
8. Використання робочих місць за період (з підсумками по класах)
9. Активність користувачів за період
10. Технічний стан робочих місць по класах
11. Перевірка розкладу на конфлікти

## Класи типів

| Клас | Призначення |
|---|---|
| `Entity` | опис таблиці: назва, стовпці, ID запису |
| `Repository` | CRUD з реалізаціями за замовчуванням та перевірка `conflicts` |
| `Referable` | вибір запису іншої таблиці для зовнішнього ключа |
| `Displayable` | вивід записів таблицею |
| `Inputable` | введення нового запису і коригування наявного |
| `Validatable` | перевірка запису без звернення до БД |
| `DbEnum` | відповідність Haskell-типів значенням `ENUM` |
| `FieldInput` | розбір і показ значень полів |
| `WebField` | тип поля у веб-формі (текст, число, час, дата, список) |
| `WebForm` | опис веб-форми запису |

Також програма реалізує:
- екземпляри класів бібліотеки `mysql-simple`: `QueryParams`, `QueryResults`, `Param`, `Result`;
- екземпляри `Functor` та `Applicative` для двох власних типів:
  - `RowParser` читає рядок результату SQL-запиту;
  - `Form` описує веб-форму. З одного опису програма отримує список полів, значення запису для
    редагування і розбір введених даних, причому помилки всіх полів збираються разом.

Узагальнене меню `crudMenu` і веб-маршрути CRUD працюють з будь-яким типом, що має потрібні екземпляри.
Звіти описані як дані: параметри і функція, що повертає таблиці. Тому обидва інтерфейси використовують
одну реалізацію кожного звіту.

## Структура проєкту

```
app/Main.hs            точка входу, вибір інтерфейсу, підключення до БД
src/Config.hs          параметри підключення
src/Types.hs           типи даних (записи таблиць, перелічення)
src/Classes.hs         власні класи типів
src/RowParser.hs       парсер рядків результату (Functor/Applicative)
src/Input.hs           консольне введення, клас FieldInput
src/Form.hs            веб-форми (Functor/Applicative), класи WebField і WebForm
src/Table.hs           вивід таблиць у консолі
src/Errors.hs          зрозумілі повідомлення про помилки БД
src/Instances/*.hs     екземпляри класів для кожної таблиці
src/Registry.hs        список таблиць для обох інтерфейсів
src/Reports.hs         звіти
src/Menu.hs            консольне меню
src/Web.hs             веб-сервер (JSON API, бібліотека scotty)
web/                   сторінка: index.html, style.css, app.js
sql/schema.sql         структура БД
sql/seed.sql           тестові дані
```
